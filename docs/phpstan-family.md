# The PHPStan family — decision record

Part of the [rule-model design record](rule-model.md), split out per family; the contract, the doctrine, the cross-family decisions, and the roadmap live there. Entries are chronological under their original headings. The import rule's behaviour table lives in the R2 decision in the core record.

## Decided 2026-07-17 (R3, first member) — `PhpStanMinLevel` reads only what is written

The first value-aware rule, and the first real abstainer. Its semantics against phpstan's include-merge behaviour (the including file's scalar parameters override included ones):

- A written `level` below the floor is raised by a targeted replace of just the value (indentation and a trailing comment survive); at or above the floor — including `max` — the content returns unchanged, so in-sync falls out of the derived check.
- **A missing `level:` line follows the author's `OnMissing` choice** (`Core/Rule/OnMissing`, deliberately generic from day one — every future value-aware rule faces the same question). `Skip` (the default) leaves it to whatever owns the effective value: the rule is include-blind by design (resolving `includes:` needs filesystem access, breaking purity), and in an import-based setup the shared ruleset ships with the floor as its own level — pinned by a test in the org package, not the engine. `Write` writes the floor (first child of `parameters:`, or a new section at the end) for setups where nothing else supplies a level, which otherwise runs phpstan at its default level 0 with the floor silently unenforced. Skip is the default because writing is the dangerous direction: the project file wins phpstan's merge, so blindly writing the floor could *lower* a stricter imported level. *(Revised 2026-08-04: the floor now creates on an absent config and always writes a missing level — the `OnMissing` seam was removed the same date; see [the revision note below](#revised-2026-08-04--enforce-over-silence-the-floor-creates-on-absence-and-write-becomes-the-default).)*
- Only the level line directly under `parameters:` counts (matched on the section's child indentation) — a nested `level` key from an extension (`type_coverage:`) is never touched.
- Composition with the import rule is fold order: the import rule declared first creates a missing config, and the floor rule then judges real content instead of abstaining (pinned by the `phpstan-family` scenario).
- **`PhpStanLevel` value object**: the level grammar — bounded 0..10, the `max` alias, quoted config values, refusal of unjudgeable values (`%level%`) — lives in one value object (`fromInt()`, `createMax()`, `fromConfigValue()`, `isAtLeast()`), because a bare `int` could not express a floor of `max` and left the grammar scattered as primitives in the rule.
- **`PhpStanPinnedValues` (2026-07-17)** — the third strength between import-defaults and bounds: *pin exact values the project may not override*. The import alone cannot stop overrides (the project file wins phpstan's merge); a pin rewrites deviations on every sync. Configured as a `PinnedValues` value object (nested string keys, scalar leaves — bool/int/string; list pinning is a separate union-semantics discussion, deferred). A pin always writes — no `OnMissing` (writing is its point) — and an absent config is created holding the pins. No `ExplainsDrift`: a pinned-value diff is self-evident. Org-author guidance, worth repeating wherever pins are documented: defaults belong in the imported ruleset; pin only what must not be overridden.
- **`Formats/` — format machinery is its own layer (2026-07-17).** The pin rule's editing mechanics (find a section, walk a key path, replace or insert a scalar line, create missing keys as a section's first child, missing top-level sections appended at the end) are facts about neon, not about phpstan, and they serve multiple rule families — unlike the block family's marker machinery, which has one family and lives with it. They live in `Formats/Neon/NeonScalarWriter`, a new deptrac layer: `Rules → Formats → Core`, and `Core ↛ Formats` keeps the engine format-blind. Still targeted line edits — no parse, no reserialization (the recorded anti-goal). Fail-loud where a scalar pin meets a section or a section path meets an inline value. `PhpStanMinLevel` migrates onto it when next touched.

### Revised 2026-08-04 — enforce-over-silence: the floor creates on absence, and `Write` becomes the default

Decided during the psalm family's design (the doctrine emerged there — see [the psalm design note](psalm-family.md#designed-2026-08-04--two-rules-over-the-first-xml-writer-enforcement-without-abstention) — and was applied here first, deliberately: the family's existing behaviour catalog turns every consequence into a visible fixture diff, so the shared half of the psalm design is validated before its new half is built). Two changes to the floor; the rest of the entry stands:

- **`apply(null)` creates a self-carrying config** (`parameters:` holding just the floor) instead of abstaining, joining the import's and the pin's creation doctrine: declaring the rule means the level is enforced, and `withoutRule()` is the opt-out. The include-blind caution does not bind an absent file — no file means no `includes:`, so nothing else *can* own the effective level, and phpstan would run at its default level 0. Creation ignores `OnMissing` (that choice governs a missing line, not a missing file). The family fold is unchanged: the import declared first still creates, and the floor then judges real content.
- **`OnMissing` defaults to `Write`; `Skip` becomes the org's explicit vouch** that an imported ruleset owns the effective level — declared visibly, next to the org-test discipline that pins the ruleset's own level. A declared floor now enforces a level in every case except under that vouch, closing the hole where an import-less org's floor sat silently unenforced on configs without a level line.
- Considered and rejected on the way, in discussion order: keeping `Skip` as the default (the silent hole above); an includes-aware `Auto` (write when the config has no `includes:`, skip otherwise — its skip branch can still go silently unenforced when the chain carries no level); the same `Auto` refusing instead of skipping (loud, but the refusal lands in consumer repos for what is an org-side declaration gap, and the near-universal baseline include — `phpstan-baseline.neon` — would trigger it on most mature projects while owning no level at all).
- The `Write` default's accepted trade-off, with its mitigation: a consumer's own level-setting include can be overridden by the written floor — the project scalar wins the merge — but the write is a visible `level:` line in a sync diff that is reviewed before it lands (the recorded review discipline), and the consumer's fix, writing their intended level explicitly, is permanent. The ownership consequence is deliberate: with a written line the import no longer carries the level; orgs that want import ownership say so with the vouch. Discoverability of that choice deliberately rides the generated rule-catalog docs, not more prose here.
- Noted for a later look (2026-08-04): with `Write` as the doctrine default, psalm needing no `OnMissing` at all, and the Rector floor parked, the seam's shipped scope had narrowed to this one rule's vouch. The later look arrived the same day — the seam is removed; see the closing note.

**Removed the same date.** Taken to its conclusion after the vouch's remaining mechanics were designed to the end (a plan-time refusal guard for the one contradictory corner — a Skip-vouched floor meeting an absent config — was drafted and shown): the constructor parameter and the `OnMissing` enum are deleted, and the floor always writes. The weighing: the two patterns only the vouch could express — import-owned levels riding `composer update`, and a shipped default stricter than the floor — were judged not worth an org-facing knob against the unconditional guarantee, under which the rule's description ("keeps the level at or above N") holds without the vouch's asterisk. The escape hatches survive without the seam: an org that does not want floor enforcement declines to declare the floor (the shipped ruleset plus its org test remain that mechanism), and a consumer opts out via `withoutRule()`. Re-add path if a real org ever demands vouch semantics: an optional constructor parameter, backward-compatible — removal now, pre-release, is the cheap direction. Requirement recorded for the package docs (README / rule catalog): the always-write behaviour must be documented clearly for consumers — what the written level line is, that raising it is always free, and that the sync reverts lowering — because the first confused question after adoption will be about exactly that line. The removal landed together with the floor's `NeonScalarWriter` migration (the recorded 2026-07-17 intention): the writer gained a `read()` operation, and the rule's level-line matcher, floor writer and created-config rendering collapsed into read + write calls.
